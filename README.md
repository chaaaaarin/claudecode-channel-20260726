## 1. 前回のおさらいと今回の違い

前回の資料では、Thariq氏の「Claude Codeのシステムプロンプトを80%以上削除しても、コーディング評価上の性能低下は無かった」という発表を扱った。✅ あれは「なぜプロンプトの常識が変わったか」という総論だった。

**今回はその続編**——Opus 5というモデル1つに絞って、公式ドキュメントが「ここを直せば十分」と挙げている7つの具体的な挙動パターンを見ていく。前回を見ていなくても、この資料単体で完結する。⚠️（前回との接続づけは本資料側の構成であり、公式が「続編」と位置づけているわけではない）

## 2. Opus 5、本当の実力（公式チャート）

Claude Opus 5は2026年7月24日発表。✅ 価格は入力$5・出力$25（100万トークンあたり）で、前モデルのOpus 4.8と同額。✅ コンテキスト長は1Mトークンがデフォルト兼上限。✅

難しいコーディング課題を測る内部評価「Frontier-Bench v0.1」では、Opus 5はOpus 4.8の**2倍以上**のスコアを、より低いコストで達成した（公式チャートは[スライド](https://chaaaaarin.github.io/claudecode-channel-20260726/slides.html)で図示）。✅

未知の問題を解く力を測る「ARC-AGI-3」でも、Opus 5のスコアは次点モデルの**約3倍**。✅ ただし同じ公式チャートを見ると、OpenAIのGPT-5.6 Solは低コスト帯で健闘しており、「効果は最上位だが値も張る」Opus 5と「そこそこの性能を安く」というOpenAI側の設計思想の違いも透けて見える。🔶（この対比の解釈は本資料側）

| 指標 | Opus 5 | Opus 4.8 | 備考 |

| Frontier-Bench v0.1 | 2倍以上 | 基準 | ✅ 公式チャートより。同等コストで比較した場合 |
| ARC-AGI-3 | 次点の約3倍 | ー | ✅ 公式ブログ本文に明記 |

## 3. でも実際どうなの？——実名レビューの本音

公式発表だけでは見えない実感もある。Every社の共同創業者・CEOであるDan Shipper氏は、発表直後に自身のXアカウントで次のように評した。✅（本人アカウントで直接確認）

> 「これは貧乏人のFableだ。Fableの天才性なしに、Fableのパーソナリティの癖をたくさん持っている」

同氏によれば、Every社が使っている大規模スキルセット「Compound Engineering」と組み合わせると、Opus 5は指示に反論したり、作業を終える前に止まったりした。✅ 同僚のKieran Klaassen氏は、既存スキルを削除しゼロから始めると劇的に改善すると発見した。✅ Dan Shipper氏自身も、自分のワークフローには「最難関タスク用の天才モデル(現Fable)」「それ以外全部用の賢く速い汎用モデル(現GPT-5.6)」という2つの枠があり、Opus 5はどちらにも収まらない"奇妙な中間"だと評している。✅

もう一人、ChatPRD創業者でポッドキャスト"How I AI"を主催するClaire Vo氏は、Lenny's Newsletter掲載のレビューで「一緒に働くのは嫌い」と述べつつ、7モデルのブラインドテストでは全モデル中トップにランクするという矛盾した評価を報告している。🔶（同氏のポッドキャスト本編は音声のため、概要・二次情報での確認）性格を「neurotic（神経質）」と表現し、冗長さの問題を自ら「Claude Slop」と名付け、マージコンフリクトの処理を拒否した実例も報告した。🔶

この体験談は、次章で見る公式ドキュメントの内容——「指示を足すより、引く」というOpus 5の基本方針と符合する。⚠️（符合の指摘は本資料側の解釈）

## 4. 核心：Opus 5固有の7つのクセと直し方

公式ドキュメント「Prompting Claude Opus 5」は、Opus 4.8からの変更点のうち、特にプロンプトの手直しが必要な7つの挙動を挙げている。✅ 全文コピペ可能な処方箋は[プレゼントキット](#kit)にまとめた。

| # | クセ | 直し方の方向 |
|---|---|---|
| ① | 応答が長い（effortを下げても短くならない） | 簡潔さを明示的に指示する |
| ② | 作業中に逐一実況する | 実況のリズムを指定する |
| ③ | 書き出す資料そのものが長い | 資料の長さを別途指示する |
| ④ | 頼んでもいない確認・範囲拡大をする | 旧来の検証指示を削除し、範囲を明示する |
| ⑤ | サブエージェントを分身させすぎる | 委任条件と上限を明示する |
| ⑥ | 些細な言い直しを逐一報告する | 報告する訂正の基準を絞る |
| ⑦ | thinking無効時に出力が漏れる（開発者向け） | thinkingは切らずeffortを下げるのが基本 |

✅（7項目とも公式ドキュメント本文で直接確認）

例えば④について、公式ドキュメントは次のように述べている。✅

> "If your prompt contains explicit verification instructions ('include a final verification step for any non-trivial task,' 'use a subagent to verify'), remove them: instructions like these cause over-verification on Claude Opus 5, and removing them reduces wasted tokens with no loss in quality."

つまり「検証しろ」という指示を足すのではなく、**むしろ消す**ことが処方箋になっている。これは前回扱った「指示は足すより引く」という大きな流れの、Opus 5における具体例と言える。⚠️（前回との接続の指摘は本資料側）

## 5. 意外な発見：Fable 5とは真逆の指示

7つのクセのうち⑤「サブエージェントの分身」は、特に興味深い。同じAnthropicの公式ガイドなのに、**Fable 5には正反対の指示**が書かれているからだ。✅

| 観点 | Fable 5 | Opus 5 |
|---|---|---|
| サブエージェントへの委任 | 積極的に委任せよ、と明示 | 委任を絞れ・上限を決めよ、と明示 |
| 応答の長さ | effortとある程度連動 | effortは思考量のみ。話す量は別指示が必要 |
| 価格（入力/出力・per Mtok） | $10 / $50 | $5 / $25 |
| コンテキスト長 | 1Mトークン | 1Mトークン |

✅（両モデルの公式ドキュメントで直接確認）

モデルを使い分けているプロジェクトでは、「Claude用の指示」をひとまとめにして使い回すと、片方のモデルには逆効果になる指示が混ざる恐れがある。⚠️（この一般化は本資料側の解釈）

## 6. Effort（努力度）の使い分け

Opus 5はlow・medium・high（既定）・xhigh・maxの5段階すべてに対応する。✅ 公式ドキュメントは「まずhigh（既定）のまま試し、evalで質が落ちないと確認できたらlow/mediumを積極的に使う」ことを勧めている。✅

注意点として、Opus 5では**thinkingがデフォルトでON**になり、effortがhigh以下でないとthinkingを無効化できない（xhigh/maxとdisabledの組み合わせは400エラーを返す）という破壊的変更がある。✅ Opus 4.8からの移行時は要確認。

出典（公式）: [Effort](https://platform.claude.com/docs/en/build-with-claude/effort) ／ [migration guide](https://platform.claude.com/docs/en/about-claude/models/migration-guide)

## 7. 今日からやること（始めるならこの順番）

1. **CLAUDE.md・システムプロンプトを棚卸しする** — 旧モデル向けの「検証して」「ダブルチェックして」という指示が残っていないか確認する
2. **応答の長さを整える** — 長いと感じたら「簡潔に」の一言を足す（effortを下げるだけでは直らない）
3. **サブエージェントの委任条件を明示する** — 委任してよい条件と上限（スポーン数）を決める
4. **thinkingは基本、切らない** — 無理に無効化せず、まずeffortを下げて様子を見る
5. **[プレゼント①](#kit)の処方箋7選から、症状が当てはまるものだけ試す** — 全部を一気に入れ替えない

## 8. 反論の先回り・注意点

**「公式が『2倍』と言っているなら無条件にすごいのでは？」**——ベンチマークの数値は測定条件（ハーネス・試行回数・effort設定）に依存する。✅ 公式チャート自体も、低コスト帯ではGPT-5.6 Solが健闘する場面を示しており、「あらゆる場面でOpus 5が最強」という単純化はできない。🔶

**「実名レビューの『貧乏人のFable』は信頼できるの？」**——Dan Shipper氏・Claire Vo氏とも実名・検証済みアカウントで、Every社・ChatPRD/Lenny's Newsletterという実在の媒体を持つ発信者ではあるが、あくまで個人の使用感であり、全体の評価を代表するものではない。🔶 ただし「大きな指示書と組み合わせると作業を止めすぎる」という具体的な現象は、公式ドキュメントが挙げる「引き算が効く」という方針と方向性が一致している。⚠️（一致の指摘は本資料側の解釈）

**「7つの処方箋を全部入れるべき？」**——公式ドキュメントも「Opus 4.8のプロンプトのままでも概ね動く」と述べており✅、症状が実際に出ている箇所だけ、優先度をつけて手直しするのが安全。

## 10. まとめ

Opus 5は「喋りすぎ・確認しすぎ・分身させすぎ」という、公式ドキュメント自身が認める7つのクセを持つ。だが直し方はどれも一言のプロンプトを足すだけで完結し、その多くは「足す」より「引く」——旧モデル向けの指示を削ることが処方箋になっている。同じAnthropicのFable 5とは真逆の指示もあるため、モデルをまたいだ設定の使い回しには注意したい。
